# Incident implementation

The immutable fixture records amounts in fils (100 fils = AED 1). Source transactions, batch membership and the ordered delivery attempts determine the ledger, event log and plot. A failed acknowledgement after a committed write makes one batch appear twice.

The browser runs DuckDB-Wasm in a dedicated worker and loads a same-origin binary. A repair is a bounded, single-table SELECT returning transaction_id and amount_fils. In-memory transactions isolate replay datasets. The verifier compares the full multiset of ID/amount pairs with an independently constructed reference for each probe. The additional transaction in the final probe uses the same amount as an existing one and arrives on attempt two.

React owns navigation and session state. Each verified receipt records its exact SQL and case version. The optional mentor service receives a selected case question and evidence identifiers. The server controls the allowed evidence and keeps its model credentials outside the browser.
